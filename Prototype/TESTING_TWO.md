# Prototype #2
The second prototype improved substantially on the first; it achieved closed-loop self-balancing, holding itself upright at its equilibrium point with only small, slow oscillations when placed on the floor near the balance angle, and correctly recovering from static displacements of ±10° or more. It consistently found a clean balancing point or was able to remain upright for over two minutes.  This used the same wooden chassis design as prototype #1 but laid flat with wheels mounted underneath, running an ESP32, MPU6050 (complementary filter for pitch), and a TB6612FNG driving two DC motors, tuned with a proportional-derivative-cubic PID variant (output = Kp*error + Kc*error³ + Kd*derivative).

Getting to that point required working through many discrete hardware failures along the way: a pin-mapping mismatch between two versions of the sketch (motor B's PWM and direction pins were swapped relative to the physical wiring, which made it stall on direction changes and spin opposite to motor A), an MPU6050 that stopped responding on the I2C bus entirely (diagnosed via direct-jumper scanner tests, likely fried, replacement ordered), and general breadboard connection instability consistent with prior builds.

This prototype's big limitation is that it cannot yet recover from pushes. It balances reliably from rest but a moderate disturbance causes it to fall every time. Diagnosis pointed to two causes: the controller initially had no derivative term, so it could only react to the current tilt angle and had no mechanism to counter angular velocity from a push before the tilt built up; and the chassis's low, flat mass distribution (wheels underneath a horizontal board) produces fast pendulum-fall dynamics, leaving little margin for the control loop to react in time. Loop latency (four sequential blocking I2C register reads plus unthrottled serial output each iteration) was also identified as a likely contributor, but I’d need to do more testing.

The next prototype will keep the same electronics and control approach but reorient the chassis upright, moving the motor mounts to the now-bottom (originally narrow) face to raise the center of mass and slow the fall dynamics, while adding popsicle-stick side guards to protect wiring during the repeated intentional falls involved in tuning. Planned software changes include a properly tuned derivative term Kc, the cubic proportional term to allow aggressive correction at large angles without over-reacting to small drift, a hard cutoff to disable motors past a non-recoverable tilt angle, and reduced loop latency via a single burst I2C read and throttled serial output. In short: I’m adding parabolic speed control and some guard rails to the design.
